# M0: итоги проверки технологий

Дата: 8 ноября 2026. План: [prototype-plan.md](prototype-plan.md).

## Что сделано

```
packages/
  core/     — мерки (пока 4), тестовая деталь на движке FreeSewing, нейтральная геометрия в мм
  export/   — SVG 1:1 и PDF: разбивка на A4 с метками склейки, A0, контрольный квадрат 10×10 см
  body/     — тело Anny в браузере: порт формулы фенотипа, пересчёт формы
  viewer/   — 3D-просмотр на Three.js
apps/web/   — прототип (Vite + React, PWA): вкладки «Выкройка» и «Манекен»
tools/anny-export/ — выгрузка Anny из Python в бинарный формат для браузера
```

Команды: `pnpm install`, `pnpm dev` (прототип), `pnpm check` (линтер, типы, тесты), `pnpm build`, `pnpm make-test-pdf out` (PDF тестовой детали в папку `out`).

## FreeSewing (`@freesewing/core` 4.10.2, MIT)

**Вывод: берём**, но держим за тонкой прослойкой.

- Точки, прямые, кривые Безье, вытачка, припуск через `offset`, длины срезов — всё работает. Тестовая деталь (четверть прямой юбки с вытачкой) строится за ~8 мс в браузере.
- Ядро отдаёт наружу свою геометрию (`Piece`: пути SVG в мм с ролями «срез», «линия шва», «долевая», «сгиб»). Экспорт и интерфейс не знают про FreeSewing, поэтому движок можно заменить, не трогая остальное.
- Недостатки, которые учли:
  - пакет без типов TypeScript, пишем свои (`packages/core/src/drafting/freesewing.d.ts`);
  - в версии 4.10.2 у `@freesewing/core-plugins` не прописаны зависимости `@freesewing/plugin-transform` и `@freesewing/config`, ставим их явно;
  - `offset` сдвигает весь контур, а деталь со сгибом требует собирать линию среза по частям (сделано вручную);
  - их плагины печати завязаны на их сайт, поэтому PDF делаем сами на `pdf-lib` (MIT).
- Печать: A4 — 6 листов (2 × 3) с рамкой, именами листов (А1, А2, Б1…) и метками склейки; A0 — один лист. PDF ~14 КБ, собирается за ~250 мс. Шрифт DejaVu Sans встраивается подмножеством (стандартные шрифты PDF не умеют кириллицу).

Осталось проверить руками: распечатать A4 на обычном принтере и измерить контрольный квадрат.

## Anny (`anny` 0.6.2, код Apache 2.0, ресурсы MakeHuman CC0)

**Вывод: подходит для телефона, проверено на настоящем устройстве.**

- Сетка: 13 718 вершин, 27 420 треугольников.
- В исходной модели 624 смеси фенотипа (пол, возраст, мышцы, вес, рост, пропорции, грудь, упругость, этничность) — это ~100 МБ. Мы оставили точную формулу весов фенотипа (порт на TypeScript совпадает с Python), а сами смещения вершин сжали методом главных компонент по выборке взрослых фигур.
- Точность сжатия на отложенной выборке:

  | Ранг | Средняя ошибка | 99 % вершин | Худшая вершина |
  | --- | --- | --- | --- |
  | 32 | 0,24 мм | 1,7 мм | 9,7 мм |
  | **48 (выбран)** | **0,10 мм** | **0,8 мм** | **5,1 мм** |
  | 64 | 0,05 мм | 0,4 мм | 3,1 мм |

- Плюс 13 точных «местных изменений» Anny с именами мерок: обхваты груди, под грудью, талии, бёдер, шеи, бедра, плеча, ширина плеч, длина спины до талии, высота бёдер и др. Их на M4 будем подбирать, чтобы обхваты на манекене совпали с мерками.
- Размер файла тела: 5,0 МБ (4,0 МБ в gzip). Грузится один раз, потом из кэша (PWA).
- Скорость пересчёта формы в браузере (Chromium, эмуляция Pixel 7, процессор замедлен в 4 раза как замена среднему телефону): ~20 мс на пересчёт, ~45 мс вместе с нормалями и выводом. Для ползунков этого хватает.
- **Проверка на настоящем телефоне** (Android, Chrome, прототип с GitHub Pages, 8 ноября 2026): загрузка 4,0 МБ (в gzip) за 1,9 с, первый пересчёт 27 мс, затем в среднем 4 мс на пересчёт, 60 кадров в секунду. Телефон справляется с запасом, воркер пока не нужен.
- Для выгрузки нужен Python и PyTorch (`tools/anny-export`). Готовые файлы лежат в `apps/web/public/body/`, так что разработчикам и CI PyTorch не нужен.
